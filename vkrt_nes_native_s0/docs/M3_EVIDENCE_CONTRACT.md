## Hardware contract

All bank logic lives behind the existing first-party Mapper abstraction. The
Machine supplies bus-cycle starts to `cpu_write_cycle`, including each RMW write.
The default adapter preserves NROM/MMC3 behavior. Mapper identities are metadata,
never ROM/game-specific branches. All board state encodes in canonical version 3;
the existing NROM/MMC3 encoding itself is unchanged.

| Mapper | Accepted baseline | Banking and policy |
| --- | --- | --- |
| 1 MMC1 | Submapper 0; 16..256 KiB PRG; 0..128 KiB CHR | Five LSB-first writes, fifth address selects register; bit 7 always resets shift and ORs Control with $0C; immediately consecutive data writes ignored using bus cycles; all four PRG/control modes and both CHR modes; one-screen A/B, vertical, horizontal; 8 KiB PRG-RAM with bit-4 disable |
| 2 UxROM | 32..256 KiB PRG, 8 KiB CHR-RAM | Selected 16 KiB low PRG and fixed final high bank; fixed header mirroring; legacy/submapper 0 chooses no conflict; NES 2.0 submapper 1 no conflict, 2 AND conflict |
| 3 CNROM | 16/32 KiB fixed PRG, 8..32 KiB CHR-ROM | 8 KiB CHR bank; fixed header mirroring; legacy/submapper 0 chooses original-board AND conflict; NES 2.0 submapper 1 no conflict, 2 AND conflict |
| 7 AxROM | Submapper 0; 32..256 KiB PRG, 8 KiB CHR-RAM | 32 KiB PRG bank; bit 4 selects physical nametable A/B; baseline no conflict |

ROM sizes must be powers of two. Zero CHR size on MMC1 selects 8 KiB CHR-RAM.
CHR sources identify physical 1 KiB banks, and mutation epochs belong to physical
RAM banks. Both follow remapping; identical writes do not advance epochs. High
plane epoch values also identify the selected physical bank. A trainer initializes
$7000-$71FF. As with the existing NROM compatibility memory model, discrete boards
expose deterministic 8 KiB PRG-RAM; that is not a claim that every physical discrete
board contains RAM. MMC1 disabled reads return zero and writes are ignored.

AND conflict is `written_value & old_mapping.cpu_read(write_address)`, evaluated
before the bank changes. Legacy policies deliberately resolve ambiguous headers;
they do not identify the physical board. MMC1/AxROM four-screen declarations are
rejected; fixed four-screen semantics on other accepted mappers are preserved.
NES 2.0 extended RAM, exponent sizes and non-NTSC declarations remain rejected.
No SUROM/SOROM/SXROM outer wiring, MMC1A-specific RAM, mapper 105/185, MMC5,
MMC2/MMC4, VRC, FDS, PAL/Dendy, battery persistence or state restore is earned.

NTSC controller reads hold one serial bit while DMA holds the CPU address through
halt/dummy/alignment. The sample get releases controller /OE, so resuming the CPU
read clocks again: one bit is deleted on the addressed port. Each bus clock and
trace event remains in the existing scheduler. Controller bits 7-5 still come
from open bus, including the sample byte's drive. No random errors or bus decay.

Sprite evaluation uses a 32-byte secondary OAM, eight primary-slot identities,
n/m counters, read latch, write address, selected count, overflow-copy tail and
search-complete flag. Clear runs on even dots 2-64. Visible dots 65-256 read on
odd dots and operate on even dots. After eight complete sprites, misses advance
n and m independently, producing diagonal false positives and false negatives.
The first match sets overflow and drains the suppressed copy. Search does not
wrap beyond primary slot 63. Fetch units consume secondary OAM at dots 257-320.
Sprite-0/order and physical CHR fetch provenance remain intact. Either rendering
bit enables evaluation; disable never clears overflow. Pre-render dot 1 clears
status even when rendering is off. Row 239 evaluates; Y=240/255 do not wrap in.

The model initializes evaluation bookkeeping at row dot 1 and stops comparison
after the first overflow match. It does not qualify every rendering-toggle/OAMADDR
edge, post-match idle OAM bus activity, $2004 corruption, OAM DRAM decay or
transistor-level behavior. No prediction based on future OAM contents or frame
status reads is used. No frontend, renderer or neural/temporal scope was added.

## R0.2 independent legacy-screen oracle correction

R0.1 used the modern `$6000-$6003` status convention for legacy screen-reporting
programs that do not implement it, so those timeouts were not pass/fail evidence.
R0.2 leaves ROMs and production code untouched and links a read-only adapter to
the same core. After bounded frame budgets it reads physical nametable bytes.

The corrected set is seven deterministic screen oracles: `cpu_dummy_reads`
requires `Passed`; the two `read_joy3` programs require `Conflicts:` and
`Errors:` with `/1000`; and sprite-overflow 1.Basics, 2.Details, 3.Timing and
4.Obscure require `Passed`. The pinned corpus's 5.Emulator case is excluded
because that corpus itself marks it failing. Every selected ROM runs twice and
must reproduce identical screen text, state hash, cycle count and DMC fetch count.

This is bounded harness adjudication, not production special-casing and not a
claim about every controller error-rate distribution or sprite/OAM edge.
